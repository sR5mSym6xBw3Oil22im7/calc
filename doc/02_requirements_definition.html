1. 要件定義の方針

本書は、現行ソースから確認できる動作を機能要件・非機能要件として整理し、受入時に観察できる条件を明記します。音声入力の正式対象はGoogle Chrome for Windows 11 / Linuxです。

2. 機能要件

ID要件受入条件状態
FR-001初期表示時、主表示を0として表示する。起動直後のmainDisplayが0。実装済み
FR-0020～9をボタン・キーボードから入力できる。入力値が表示へ反映される。実装済み

FR-018「クリア」「削除」「パーセント」「イコール」を単一操作として解釈する。対応ボタン相当の処理が動作。実装済み

FR-021発話末尾に評価語がある場合、演出完了まで電卓入力をロックする。花火完了後に解除される。実装済み
FR-022音声エラー時にエラー状態を表示し、セッションをリセットする。ERROR表示後、規定時間でIDLEへ戻る。実装済み

3. 非機能要件

ID分類要件確認方法
NFR-001互換性正式対象はGoogle Chrome for Windows 11 / Linux。両OSで実機確認。
NFR-002セキュリティ音声・認識結果をアプリ独自に永続保存しない。Storage/送信処理がないことを確認。
NFR-003権限音声利用時のみマイクアクセスを要求し、停止時にMediaStreamトラックを停止する。権限ダイアログと停止処理を確認。
NFR-004操作性ボタン・キーボード・音声が同一の計算ロジックへ到達する。同じ入力で同じ結果。
NFR-005レスポンシブ幅540px以下でパディング・キーサイズ等を縮小する。Chrome DevToolsと実画面。
NFR-006アクセシビリティ主要出力にaria-label/aria-live、マイクにaria-pressedを設定する。DOM属性確認。
NFR-007動き低減prefers-reduced-motion: reduce時にアニメーション時間を極小化する。OS設定/DevToolsで確認。
NFR-008保守性計算、音声、演出、テーマを名前付き関数・定数へ分離する。script.js構造確認。
NFR-009配布性ビルド工程なしで静的ホスティング可能。HTML/CSS/JSのみであること。
NFR-010表示性能Canvas DPRを上限付きで設定し、画面非表示・リサイズ時に花火を停止する。実装・動作確認。

4. 音声入力の受入条件

  1. Windows 11版Chromeでマイク許可後、「12たす3イコール」により15が表示される。
  2. Linux版Chromeで同等の音声認識開始・停止ができる。
  3. マイク許可を拒否した場合、ERROR状態になり、アプリ全体が停止しない。
  4. 非Chromeでは音声入力UIが表示されない。
  5. 音声計算で評価語を含む場合、花火演出中は追加入力が抑止され、完了後に操作可能へ戻る。
  6. 音声認識結果が永続保存されない。
