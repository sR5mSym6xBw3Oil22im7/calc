2. 目的

4ファイルをローカル配布または静的Webサーバーへ安全に配置し、確認・障害時の復旧を行う。

3. 適用範囲

README.md、index.html、style.css、script.jsの配布・配置を対象とする。公開先固有の操作は要確認である。

5.2 事前確認・バックアップ

  1. ZIP/作業ディレクトリのハッシュまたは版識別子を記録する。
  2. node --check script.jsで構文を確認する。
  3. index.htmlからstyle.css/script.js、Google Fontsの参照を確認する。
  4. 旧版フォルダを日時・版付きで複製し、復旧可能性を確認する。
  5. 未実施テストと既知問題を承認者へ提示する。

5.3 ローカルファイルとして配布する場合

  1. 4ファイルの同一階層を維持したフォルダを作る。
  2. 配布用ZIPへ格納する。
  3. 受領側で展開後、index.htmlをブラウザで開く。
  4. FT-001、FT-006、FT-009、FT-010、KT-003、UIT-003をスモーク確認する。
  5. Google Fonts未取得時も計算できることを確認する。

5.4 静的Webサーバーへ配置する場合

  1. 公開ディレクトリと権限を確認する。
  2. 旧版をバックアップする。
  3. 4ファイルを同一相対構成で一時領域へ配置し、可能なら原子的に切替する。
  4. 公開URLでHTTP 200、CSS/JS/Fonts取得、Consoleエラーなしを確認する。
  5. キャッシュの影響をハードリロードまたはプライベートウィンドウで確認する。
  6. スモークテスト後、リリース記録を残す。

GitHub Pages、Netlify、Vercel、AWS等の特定サービス利用は確認できないため断定しない。

5.6 問題発生時・ロールバック

誤計算、起動不能、主要キー不能、重大な表示崩れ、継続的なJavaScript例外を条件にロールバックする。新規4ファイルを退避し、バックアップ4ファイルへ戻し、キャッシュを確認してスモークテストを再実施する。

6. 前提条件・制約事項

  • 本システムは静的Webアプリケーションであり、バックエンドAPI、Web API、データベース、認証、サーバーサイド処理、バッチ、管理画面を使用しないため対象外である。
  • package.json、npm、ビルドツール、テストフレームワーク、CI/CD、コンテナは存在しない。
  • README.mdと実装が異なる場合は実装を正とする。
  • 公開先URL、本番環境、担当者、承認者、日程はソースコードから確認できない。
