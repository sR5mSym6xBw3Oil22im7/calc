2. 目的

GitHub Pagesへバージョン1.0を安全に公開し、確認・ロールバックする手順を定義する。

5.3 事前確認・バックアップ

  1. 対象4ファイルがUTF-8で保存され、参照パスが相対パスであることを確認する。
  2. テスト結果がリリース可であることを確認する。
  3. 公開前コミットIDまたはタグを記録し、ロールバック基点とする。
  4. GitHub PagesのSourceがmain／ルート（/）であることを確認する。

5.4 配置手順

  1. テストGitHubアカウントで対象リポジトリcalcへアクセスする。
  2. 変更対象をmainブランチへ反映する。
  3. index.html、style.css、script.js、README.mdの差分を確認する。
  4. mainブランチへpushする。
  5. GitHub Pagesのデプロイ完了を待つ。
  6. 公開先URLを新しいタブで開き、キャッシュの影響を避けるため必要に応じてハードリロードする。

5.5 公開後確認

  • HTTPエラーなく初期表示される。
  • Google Fontsの取得可否とフォールバック表示を確認する。
  • 数字、四則、小数点、%、AC、DEL、=、キーボード、ゼロ除算復帰を確認する。
  • PC幅とスマートフォン幅を確認する。
  • 花火とコンフェッティが表示される。

5.7 問題発生時・ロールバック

  1. 計算誤り、利用不能、主要ファイル取得失敗をロールバック条件とする。
  2. 公開前に記録した正常コミットを特定する。
  3. git revert等で問題コミットを打ち消し、mainへpushする。
  4. GitHub Pagesの再公開完了後、初期表示と主要計算を確認する。
  5. 原因、影響、対応、復旧時刻を記録する。

6. 前提条件・制約事項

  • GitHub Pages設定変更に必要な権限をテストGitHubアカウントが持つこと。
  • デプロイ完了時間はGitHub Pages側の処理に依存する。

7. 補足事項

使用しない構成

本システムでは専用のCI/CDパイプラインを使用せず、mainブランチへのpushを公開契機とする。
