2. 目的

静的Webアプリケーションとしての安定利用、障害復旧、問い合わせ、変更・リリース管理を継続的に行う。

3. 適用範囲

配布物または静的Webサーバー上の4ファイルと、外部Google Fonts依存を対象とする。アプリ固有のサーバー監視、DB監視、ジョブ監視は対象外である。

4. 用語・略語

用語・略語
用語・略語定義
静的WebアプリケーションHTML、CSS、JavaScriptをブラウザで直接実行する構成。
DOMDocument Object Model。HTML要素をJavaScriptから操作する仕組み。
CanvasJavaScriptで2次元描画を行うHTML要素。
IIFE即時実行関数式。script.js全体を閉じたスコープで実行する方式。
既知の問題原因・回避策・対応予定を管理している未解決事項。
回帰テスト変更により既存機能が壊れていないことを再確認するテスト。

5.3 障害重要度

障害重要度
重要度基準対応方針
重大電卓を利用できない、または計算結果が誤る最優先で対応
高主要機能の一部を利用できない早急に対応
中一部の表示または演出に問題がある計画的に対応
低軽微な表示差異または改善要望次回改修で検討

5.4 障害受付・初動・切り分け

  1. 日時、URL/配布版、OS/ブラウザ、画面幅、操作、入力値、期待値、実際値、Console、スクリーンショットを収集する。
  2. 重大/高の場合は変更・リリースを停止する。
  3. 計算誤りか、DOM/JavaScript例外か、CSS/フォント表示か、Canvas演出かを分類する。
  4. ローカルファイルと静的サーバー、ネット接続/切断、対象ブラウザで再現比較する。
  5. 直前正常版で再現しなければ差分を確認する。

5.5 復旧・エスカレーション

利用者の一時復旧はAC/Escape、再読込、別ブラウザ、外部フォント遮断時の待機/フォールバックで行う。誤計算または起動不能は直前正常版へロールバックする。対応期限はソースコードから不明のため要確認であり、重大度に応じた社内SLAを別途定める。

5.6 ソース・変更・回帰・リリース管理

  1. 変更要求に目的、要件ID、優先度、受入条件を付与する。
  2. DOC-05の影響範囲表でHTML/CSS/JS/テストを特定する。
  3. 作業前に版をバックアップし、変更差分をレビューする。
  4. 計算変更はFT/ET、キー変更はKT、演出変更はUIT/PTを回帰する。
  5. DOC-08を更新し、DOC-09でリリースする。
  6. バージョン、日時、変更、既知問題、担当/承認者を記録する。

ソースコード管理方式（Gitリポジトリ等）は要確認であり、ZIPのみを唯一の履歴として運用することは推奨しない。

5.7 問い合わせFAQ

FAQ
質問回答
ページを開いてもフォントが違うGoogle Fontsへ接続できない場合はsans-serifへフォールバックする。計算機能への影響はない。
Deleteキーで消せない現行はBackspaceまたは画面DELを使用する。Delete対応は要確認。
2+3*4が20になる演算子優先順位ではなく入力順の逐次計算仕様である。
%の意味は現在値を100で割る単項処理である。
花火が止まったリサイズ、タブ非表示、次の=、ACで既存花火を停止・再初期化する。
動きを減らしたいOSのreduced-motionでCSS演出は短縮されるがCanvasは現行継続する。改善課題である。
0除算後どう戻る数字キーで新規入力、またはAC/Escapeで初期化する。

5.9 保守終了時

最終版、ソース、10文書、リリース記録、障害/既知問題、外部依存、ライセンス情報をアーカイブし、公開停止または配布終了を通知する。静的サーバー利用時は公開ファイルを削除またはアクセス制御し、バックアップの保持・廃棄方針を承認する。

6. 前提条件・制約事項

  • 本システムは静的Webアプリケーションであり、バックエンドAPI、Web API、データベース、認証、サーバーサイド処理、バッチ、管理画面を使用しないため対象外である。
  • package.json、npm、ビルドツール、テストフレームワーク、CI/CD、コンテナは存在しない。
  • README.mdと実装が異なる場合は実装を正とする。
  • 公開先URL、本番環境、担当者、承認者、日程はソースコードから確認できない。
