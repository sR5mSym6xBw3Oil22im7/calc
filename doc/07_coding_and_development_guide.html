1. 基本方針

  • 静的構成（index.html / style.css / script.js）を維持する。
  • バックエンドやビルド依存を追加する場合は、既存の「そのまま配布できる」性質への影響を明記する。
  • 計算処理と音声認識処理を重複実装せず、音声は既存入力関数へ変換する。
  • 正式対象ブラウザはGoogle Chrome for Windows 11 / Linuxのままとする。

2. HTML規約

  • 日本語ページはlang="ja"とUTF-8を使用。
  • 操作要素はbuttonを使用し、状態をdata属性で識別。
  • 動的メッセージは必要に応じaria-liveを付与。
  • 装飾Canvasは支援技術から除外。
  • IDはJavaScript参照契約として扱い、変更時はscript.jsを同時更新。

3. CSS規約

  • テーマ色はCSSカスタムプロパティへ集約。
  • レスポンシブ変更は既存の540pxブレークポイントとの整合を確認。
  • 新規アニメーションはprefers-reduced-motion時の低減動作を用意。
  • 音声状態の色だけに意味を依存させず、文字ラベルも保持。

4. JavaScript規約

  • IIFEと'use strict'の現行構造を維持する。
  • 状態変更後は必要に応じてupdateDisplayまたはsetVoiceStateを呼ぶ。
  • タイマーは対応する解除処理を持たせる。
  • マイクMediaStreamは停止経路・エラー経路で必ず解放する。
  • 音声語彙追加はnormalizeVoiceText、構文追加はparseVoiceCommand、実行追加はexecuteVoiceCommandの責務を分ける。

5. 音声機能変更時の手順

  1. 追加する発話例を明確化。
  2. 正規化語彙に追加するか、構文ルールを追加するか判断。
  3. 既存の数値・二項演算・相対演算への後方互換を確認。
  4. Windows 11 ChromeとLinux Chromeの両方でマイク許可、開始、認識、停止を確認。
  5. 権限拒否、API終了、タブ切替、花火中入力ロックも回帰確認。
  6. DOC-02/03/06/08/10を同時更新。

6. ローカル確認

音声入力はセキュアコンテキスト要件の影響を受けるため、単純なfile://だけに依存せず、必要に応じてローカルHTTPサーバーを使用します。

cd calc-calc_voice
python -m http.server 8000
# Chromeで http://localhost:8000/ を開く
実公開時はHTTPSで配信してください。

7. レビュー観点

□ 計算結果がボタン・キーボード・音声で一致する。
□ 0除算、桁数、小数点重複の既存仕様を壊していない。
□ Chrome以外で音声UIが誤表示されない。
□ マイク停止時にMediaStreamを解放する。
□ 音声認識のstart競合・再起動ループを発生させない。
□ モバイル幅とreduced-motionで表示破綻がない。
□ ドキュメントの要件ID・テストケースを更新した。

8. 配布前チェック

  1. 構文エラーがないこと。
  2. index.htmlからstyle.css / script.jsを読めること。
  3. 外部フォントが失敗しても操作自体が可能であること。
  4. HTTPS公開先でマイク許可が出ること。
  5. 正式対象2環境のChromeで手動テストを完了すること。
